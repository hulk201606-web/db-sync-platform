## 1. 验收基线与三态定义

### 1.1 三态定义（严格三选一，不允许第四种表述）

| 三态 | 判定标准（必须同时满足） | 强制写法 | 典型场景 |
|---|---|---|---|
| **✅ 已验证** | ① 在指定波次内**实际执行**过；② 有可复跑命令或可复现操作步骤；③ 有落盘证据；④ 达到本文阈值 | `✅ 已验证（执行波次：Wx/Tx；证据：<路径>；复跑：<命令>）` | 一期已交付且本轮实测复核的能力；本轮实测确认「零命中 / 三值 / 零 ALTER」类否定性断言 |
| **🟡 仅提供入口** | ① 端点 / 开关 / SPI / 表结构**确实存在**且被路由或鉴权层覆盖；② 业务正路径**未实测**或**无断言覆盖**；③ 不得据此判定通过 | `🟡 仅提供入口（入口：<端点\|配置键\|表>；缺口：<未覆盖部分>）` | 19 个端点的业务正路径；`/actuator/prometheus` 有端点无任务级指标断言 |
| **⬜ 未验收** | ① 本轮未实际执行；② 或环境不可达（Docker Hub 阻断 / 客户库未到位）；③ 或实现尚未开始 | `⬜ 未验收（原因：未执行\|环境不可达\|未实现；解锁：<条件>）` | 全部 P2 / P3 未启动工作包；真库 E2E **尚未覆盖的部分**（PG 之外的方言组合 / DM8 / Oracle / DB2 真连 / 客户自有 SMTP 服务器） |

### 1.2 表结构说明（§3 / §4 的 7 列）

§3 / §4 每张表为 7 列：`编号 | 验收项 | 操作/输入 | 预期（含阈值） | 测试类型 | 证据物 | 当前状态`。
前 6 列与规定格式完全一致；第 7 列为便于 DBA / 业务方逐条打勾而增加，取值**严格限于 §1.1 三态**。
`测试类型` 取值字典（用于 §10 统计）：

| 取值 | 含义 | 是否可自动化 |
|---|---|---|
| `单元` | JUnit 单元测试 / 断言集 | 是 |
| `集成` | Spring Boot 集成测试 / API 断言 | 是 |
